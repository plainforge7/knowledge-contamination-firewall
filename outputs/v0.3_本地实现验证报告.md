## 3. 原始验证结果

- 全项目测试：65 项通过，0 项失败。
- v0.3 新增测试：27 项。
- 11 个开发／回归案例：免费确定性验证三种路径均为 11/11；该结果不是未见集成绩。
- 20 个语义 Gold：免费确定性流程验证三种路径均为 20/20；正常候选只写入测试沙盒，污染候选执行 0 次，生产路由 0 次。该结果不是模型成绩。
- 调用上限验证：Baseline 0、Single 1、Multi 普通路径 1、高风险路径 4。
- 明确 `deny` 的 Multi 路径 0 次模型调用；已验证不会进入 Single、审查者或仲裁者。
- 完整 dry-run（20 Gold × 3 次）中，Multi 有 12/20 个案例走明确拒绝短路，
  因而总成功调用数为 93（而不是固定 120）。
- 单次响应超出 Token 上限时立即停止后续调用并 `hold`；已验证不会继续发送审查者请求。
- 第三方转述与用户推断等不可信来源的冲突，不会仅因来源数量达到 2 就触发“可信冲突”升级。
- 中断/失败调用的费用不会记为 0；无用量回执会标为 `usage_unknown` 并使预算门不合格。
- 断点验证：成功记录被复用，仅基础设施失败记录被续跑；模型合同失败保留原样，不被静默重跑。
- 内存事务验证：写入前快照成功；注入写入失败后恢复到原快照。
- 隔离 TTL 验证：30 天前保持原记录；到期清除候选内容并生成结构化摘要，且不触发写入；摘要 90 天后请求删除，仅产生匿名聚合计数增量。
- 拒绝最小化验证：真实 `deny` 立即清除内容；摘要 90 天后请求删除。虚构评测诊断仅在隔离输出中保留。
- 重开验证：新 ID、新证据和旧摘要 Hash 均必需；旧 Patch、决策和确认不继承，过期摘要不能用于重开。
